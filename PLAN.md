# ЛР-2. План выполнения

**Тема:** сравнение алгоритмов поиска на прикладной задаче (C++, CLion).
**Правило работы:** этапы идут строго по порядку; следующий этап начинается только после утверждения текущего.

## Обязательные требования из задания

- решить задачу из раздела 2 методами из раздела 3, суммарный рейтинг **не меньше 55**;
- покрыть тестами основные алгоритмы;
- выбрать любой реализованный алгоритм поиска и запустить его на произвольных данных;
- проверка корректности: автоматическая (тесты, сверка с эталоном) и ручная (просмотр исходных данных и результата);
- пользовательский интерфейс (консольный);
- замер времени выполнения алгоритма;
- сравнение алгоритмов по времени на одних и тех же данных. Три случая: данные уже отсортированы, отсортированы в обратном порядке, не отсортированы. Для деревьев сравнивается время **построения** дерева;
- графики или выгрузка данных в CSV;
- ТЗ (дизайн) защищается **до** сдачи ЛР. Без защищённого ТЗ лабораторную не смотрят.

Для зачёта нужно: за качество кода не меньше 3 баллов, за объём (рейтинг) не меньше 3, за теорию больше 0, всего без оригинальности не меньше 15.

## Правила оформления кода

Источники: методичка «include-and-linking-and-templates» и книга А. Голуба «Правила программирования на Си и Си++» (номера правил указаны в скобках). Правила применяются с первого написанного файла. На этапе 9 проводится итоговая проверка по этому списку.

### Сборка, заголовки, шаблоны (методичка; Голуб 79–84, 155)
- В каждом `.h` стоит `#pragma once`.
- В заголовке подключается только то, что нужно для компиляции самого заголовка. Остальные `#include` идут в `.cpp`.
- `using namespace` в заголовках запрещён.
- В заголовках нет определений обычных (не шаблонных и не `inline`) функций, иначе компоновщик выдаст «multiple definition». Объявление пишется в `.h`, реализация в `.cpp`, и каждый `.cpp` добавлен в CMake.
- Шаблон целиком виден в месте инстанцирования: объявление в `.h`, реализация в `.tpp`, который подключается в конце `.h`. Явное инстанцирование не используется.
- Никаких трюков с препроцессором. Вместо макросов используются `const`, `constexpr`, `enum` и шаблонные функции.

### Форматирование и комментарии (Голуб 22–43)
- Отступ 4 пробела. Фигурные скобки ставятся на отдельной строке и выравниваются по вертикали (правило 42). Если тело `if`/`for`/`while` длиннее одной строки, скобки обязательны.
- Один оператор в строке. В прототипах указываются имена аргументов.
- Функция помещается на экран (около 40–50 строк). Если длиннее, её надо разбить.
- Комментарии пишутся законченными предложениями и объясняют «зачем» и инварианты, а не пересказывают код. У каждого класса и сложного алгоритма есть шапка: назначение, сложность, исключения.
- Длинные условия переносятся по операциям. Логические блоки разделяются пустыми строками.

### Имена (Голуб 44–49)
- Имена составлены из осмысленных английских слов: классы в `PascalCase`, методы в `PascalCase` (как в спецификации задания: `GetLength`, `ContainsKey`), переменные в `camelCase`, поля в `camelCase_`.
- Заглавными буквами пишутся только макросы, а их практически нет.
- Никаких имён из стандартной библиотеки и зарезервированных имён (`_X`, `__x`).

### Функции и логика (Голуб 51–78)
- Функция делает одно дело. Повторяющийся код выносится в функцию.
- Особые случаи (пустая коллекция, неверный индекс, перевёрнутый диапазон) обрабатываются в начале функции.
- Никаких магических чисел: только именованные константы.
- Не делается предположений о размерах типов. Для индексов и размеров используется `std::size_t`.
- Выделение и освобождение памяти находятся в одном классе (правило 73).
- Тесты не интерактивные (правило 75).
- Сообщение об ошибке подсказывает пользователю, как её исправить (правило 76).

### Классы (Голуб 109–153)
- Все поля закрыты (`private`). Наружу выдаются операции, а не внутренние данные: методы вроде `GetLength` и `GetCount` — это «свойства» из спецификации, а не сеттеры к каждому полю (правило 110.1).
- Константные методы помечаются `const`. Объекты, которые нельзя менять, передаются по ссылке на константу (правила 113, 120).
- Тела методов не пишутся внутри определения класса, кроме совсем тривиальных (правило 115).
- Классы с указателями-членами реализуют копирование, присваивание и деструктор (правило пяти). Присваивание самому себе обрабатывается корректно (правила 125, 126, 153).
- Используются списки инициализации членов. Объект полностью инициализируется в конструкторе (правила 127–134).
- У базовых классов и интерфейсов деструктор виртуальный (правило 139).
- Конструкторы с одним аргументом помечаются `explicit` (правило 132).
- Операции перегружаются только там, где у них очевидный смысл (`<`, `==` для ключей и кортежей), и тогда перегружается вся родственная группа (правила 145–148).
- Включение (композиция) предпочтительнее наследования. Наследование используется только для реализации интерфейсов (`IDictionary`, `ISortedSequence`) (правила 96–106).

### Исключения (Голуб 159–160)
- Исключения бросаются только для настоящих ошибок: неверный индекс, отсутствующий ключ, некорректный ввод. Используется собственная иерархия классов ошибок (`IndexOutOfRange`, `KeyNotFound`, `InvalidArgument`).
- Консольный интерфейс перехватывает их и показывает понятное сообщение. Программа не падает.

### Где сознательно отступаем от Голуба (с объяснением на защите)
Книге около 30 лет, и часть правил устарела для современного C++:
- **Правило 121** («не возвращать ссылки, только указатели»). `Get()` возвращает `const T&`. Это идиома стандартной библиотеки, а ссылка, в отличие от указателя, не бывает нулевой.
- **Правило 116** («избегать перегрузки функций»). Перегрузка используется для `operator<` и `operator==` у ключей: без них шаблонные дерево и бинарный поиск не смогут сравнивать элементы.
- **Правило 124** («operator= возвращает ссылку на константу»). Возвращается обычная ссылка `T&`, как у всех типов стандартной библиотеки; это нужно, например, для `std::swap` и шаблонного кода.
- **Правила 152–153** (`new`/`delete`, освобождение в деструкторе) выполняются, причём владение памятью сосредоточено внутри контейнеров.

### Этап 8. Консольный интерфейс
